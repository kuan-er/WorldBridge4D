# 4D Pointmap 的 Cocycle 恒等式

**日期**：2026-09-25
**性质**：理论笔记（只讲恒等式本身，不含实验）
**一句话**：我们的 4D pointmap 输出必须满足两条"绕一圈回到原点"的自洽恒等式；这两条恒等式把 cycle consistency 从经验技巧变成定理。

---

## 1. 记号

| 记号 | 含义 |
|---|---|
| `s` | **参考系**（source 帧，用它的相机坐标写出 3D 位置） |
| `t` | **物理时间**（target 帧） |
| `p` | source 帧上的像素 |
| `Ω_s` | 第 s 帧的像素网格 |
| `X[s, t, p]` | 第 s 帧像素 p 看到的物质点，在**第 t 帧时刻**的位置，用**第 s 帧相机系**表示（单位米） |
| `φ_{s→t}(p)` | 像素 p 在第 t 帧落到哪个像素；被遮挡时记为 `⊥` |
| `T_{t←s}` | 把"第 s 帧相机系"的坐标换到"第 t 帧相机系"的刚体变换 |

对应代码里的接口：`xyz[target, 3, source_y, source_x]`，其中 `source=s`、`target=t`、`(source_y, source_x)=p`。

**一个必须先说清的关键点**：`X` 的第一个索引 `s` 和第二个索引 `t` **不是同一种东西**。

- 改第一个索引 = **换坐标系**（同一件东西换个写法）
- 改第二个索引 = **走时间**（同一件东西在不同时刻的位置）

后面三条恒等式，全部来自这个不对称。

---

## 2. 恒等式 1：换参考系

对任意可见像素 `p`、任意时刻 `u`（`u` 可以和 `s`、`t` 都不同）：

```
X[t, u, φ_{s→t}(p)]  =  T_{t←s} · X[s, u, p]
```

**为什么必然成立.** 左右两边描述的是**同一个物质点、同一个时刻 u**，只是分别用第 t 帧和第 s 帧的相机坐标写出来。两个坐标系之间的换算就是一个刚体变换 `T_{t←s}`，所以两边只差这一个变换。

**关键在"与点无关".** `T_{t←s}` 只依赖 `(s, t)`，**不依赖** `p`、不依赖 `u`、不依赖那个点是什么。这正是可以把它单独拎出来当一个"换算表"的原因。

**把它自身绕一圈**：

```
T_{u←t} · T_{t←s} = T_{u←s}
T_{s←s}         = I
```

即：从 s 换到 t，再从 t 换到 u，必须等于直接从 s 换到 u；原地换等于没换。

---

## 3. 恒等式 2：换像素

```
φ_{t→u}( φ_{s→t}(p) )  =  φ_{s→u}(p)
φ_{s→s}(p)             =  p
若 φ_{s→t}(p) = q，则 φ_{t→s}(q) = p
```

**为什么必然成立.** 一个物质点从 s 帧到 u 帧只落在唯一一个像素上。先经 t 中转再走，和直接走，必须落到同一个像素。

这条把恒等式 1 里的 `φ` 也锁住了：光有 `T` 的自洽还不够，`φ` 也必须自洽。

---

## 4. 恒等式 3：换时间**没有**恒等式

```
X[s, t, p]  与  X[s, u, p]  之间没有任何约束
```

**为什么.** 这两个是同一个物质点在不同时刻的位置，差的是它自己的运动。这是物理，不是坐标变换，所以不能（也不应该）写成某个固定变换。

这条"没有恒等式"其实是最重要的一条：它说明第一个索引是坐标问题，第二个索引是物理问题，两者不能混。

---

## 5. 一个具体例子

一辆开动的车上的一个点，在第 0/10/20 帧分别落在像素 `p`、`q`、`r`：

| 恒等式 | 在这个例子里 |
|---|---|
| 换像素（恒等式 2） | `φ_{0→20}(p)` 必须等于 `φ_{10→20}(q)` |
| 换参考系（恒等式 1） | `X[0,20,p]` 与 `X[20,20,r]` 描述同一个点在同一时刻，只差 `T_{20←0}` |
| 换时间（恒等式 3） | `X[0,20,p]` 与 `X[0,10,p]` 差的是**车的运动**，无约束 |

---

## 6. 为什么叫 "cocycle"

想象你手里有一叠"换算表"：从坐标系 A 换到 B 用一张表。这些表必须满足一条最朴素的自洽要求：

> **A 换到 B、B 再换到 C，必须和 A 直接换到 C 得到同样的结果；换句话说，绕一圈回到原点必须回到原样。**

满足这种"绕一圈必须回到原点"的复合规律的一族量，数学上就叫 **cocycle**（中文常译"余循环"）。这个名字来自数学的一个分支，但你需要记住的只是它表达的那件事：**换算表必须自洽。**

SLAM 里的 **loop closure**（走一圈回来必须抵消）是同一个要求。我们平时说的 **cycle consistency** 也是同一件事——区别只是 cycle consistency 通常只检查 `A→B→A` 这一种最简单的圈，而 cocycle 说的是**所有可能的圈**都必须成立（`A→B→C→A`、`A→B→C→D→A`……）。

所以：**cycle consistency 是 cocycle 恒等式在"两帧往返"这个特例上的写法。** 它不是经验技巧，是输出的定义性质。

## 7. 两种输出系的选择 = 把恒等式放在哪里

恒等式 1 里的 `T` 有两种情形，这正好对应我们和 4RC 的差别。

**情形一：输出在第一帧世界系（4RC / V-DPM）**

如果存在一个全局世界坐标系 `W`，每帧有一个位姿 `g_s`，那么

```
T_{t←s} = g_t · g_s^{-1}
```

也就是说 `T` 完全由各帧位姿决定，恒等式**自动成立**，不需要额外约束。

- 好处：所有输出共享同一个坐标系，跨帧、跨 source 比较是免费的。
- 代价：必须先把每帧位姿 `g_s` 估准。**估错一帧，全局一致性就被破坏。**（这就是 4RC 需要 geometry head / camera head 的原因。）

**情形二：输出在逐 source 相机系（本方法）**

不存在全局坐标系，`T` 可以是一般的、非平凡的换算表，恒等式变成**要靠模型自己的输出去满足**的约束。

- 好处：不需要任何相机位姿。
- 代价：跨 source 比较必须先估 `T`；评测时对每个 `(clip, source)` 单独拟合一个 Sim(3)，对应的正是这个自由度。

> 一句话：**4RC 把恒等式"免费"了，但代价是必须估位姿；我们把恒等式变成约束，代价是少了全局坐标系。**

## 8. 与 MeanFlow 恒等式的关系

这两条恒等式和 MeanFlow（Geng et al., 2025）的核心恒等式**是同一类东西**，不是巧合。

MeanFlow 的恒等式：

```
u(z_t, r, t) = (1/(t−r)) ∫_r^t v(z_τ, τ) dτ
⟹  (t−r) · d/dt u(z_t, r, t) = v(z_t, t) − u(z_t, r, t)
```

它的本质就是 flow map `ψ_{t←s}`（把状态从时刻 s 推到时刻 t）的复合律：

```
ψ_{t←s} = ψ_{t←u} ∘ ψ_{u←s}        ψ_{s←s} = id
```

也就是同一条"绕一圈回到原点"。所以两者是**同一个形状**，只是复合律作用的对象不同：MeanFlow 作用在状态 `z` 上，我们作用在"参考系 + 像素网格"上。

| | MeanFlow | 本方法 |
|---|---|---|
| 要满足复合律的对象 | flow map `ψ_{t←s}` | `(T_{t←s}, φ_{s→t})` |
| 恒等式 | `ψ_{t←s} = ψ_{t←u}∘ψ_{u←s}` | `T_{u←t}T_{t←s}=T_{u←s}`；`φ_{t→u}∘φ_{s→t}=φ_{s→u}` |
| 学的是什么 | **平均速度** `u`（端点量） | **端点图** `X[s,t,p]`（端点量） |
| 为什么不学瞬时量 | 学 `v` 要积分才能生成 | 学局部几何 + 局部运动要积分才能出轨迹 |
| 好处 | 一步生成 | 一次 query 任意 `(s,t)`，不用积分 |
| 恒等式怎么用 | **当作训练信号**（JVP，不模拟） | 目前**没有用** |

一句话：**两者都是"不学局部瞬时量，直接学端点之间的映射，再用复合律把它约束住"。** MeanFlow 在生成模型里这么做，我们在 4D 几何里这么做。

**两点差别**（要说清，不然容易被挑）：

1. MeanFlow 是"生成元"型恒等式：它连接**平均速度 `u` 与瞬时速度 `v`**，是同一个量在两个尺度上的关系。我们的两条恒等式连接的是**不同的输出**（`s` 通道与 `t` 通道，以及未被显式输出的 `φ`），更像"跨通道一致性"。
2. MeanFlow 是单参数（时间）群，可交换；我们的时间对 `(s→t)` 不可交换，而且有 `T` 与 `φ` 两族互相耦合的传输量。

**最值得注意的推论**：MeanFlow 的**全部训练设计**都围绕逼着这个恒等式成立（用 JVP 算导数形式，而不是枚举轨迹）。而我们**完全没有施加这个约束**——模型输出 `X[s,t,p]` 时，没有任何东西强迫不同 `s` 通道之间通过某个 `T` 自洽，`φ` 甚至根本不在输出里。于是有两条便宜且有依据的改进：

1. **相邻帧版本**（对应 MeanFlow 的局部恒等式）：只约束 `φ_{t→t+1} ∘ φ_{s→t} = φ_{s→t+1}`。全 cocycle 由归纳自动成立，成本从"枚举所有圈"降到"一个相邻步"。
2. **导数形式**：对 `X` 关于 `t` 求 JVP，把恒等式写成微分形式，避免显式构造 `φ`——这正是 MeanFlow 用 JVP 的理由。

## 9. 这两条恒等式有什么用

**(1) 它是可以检查的。**
对训练好的模型，可以直接算"绕一圈差多少"：

```
像素级：  d_φ(p) = ‖ φ_{t→s}( φ_{s→t}(p) ) − p ‖
三维级：  在可见点上比较 X[s,u,p] 与 T_{s←t}·X[t,u,φ_{s→t}(p)]
```

理想情况两者都为 0。**不需要 GT 就能算**（只用模型自己的输出），所以它天然是一个自监督信号。

**(2) 它预言了"哪里会坏"。**

- 遮挡处 `φ = ⊥`，恒等式**根本无法陈述**；
- 边界处 `φ` 本身就有歧义。

所以恒等式的残差应该**集中**在边界和遮挡区域。
→ 可证伪预言：`d_φ(p)` 大的地方，EPE 也大；两者应该强相关。

**(3) 它可以作为训练正则或推理时的优化目标。**
每次训练时随机抽一个三元组 `(s,t,u)` 约束恒等式 2；推理时在共享 latent 上做几步优化，让恒等式残差变小（不需要 GT）。注意：应该做 **k 帧闭环**，不只是 `A→B→A`。

**(4) 它解释了为什么 pointmap 比 flow / track 表达力更强。**
遮挡点上 `φ_{s→t}(p) = ⊥`，对应像素**根本不存在**；但 `X[s,t,p]` 仍然有意义——它是那个被遮住的点的物理位置。
→ **pointmap 正是恒等式破裂之后仍然存在的东西。**

---

## 10. 检验条件（必须说清的边界）

恒等式本身是精确的，但从**我们自己的输出**里直接验证它，需要一个额外条件：

- 要把 `X[s,t,p]` 投到第 t 帧的像素网格上才能得到 `φ`，这需要相机内参（或者一个显式的点匹配）。
- 我们**不输出相机参数**（H023/H031 路线），所以这条恒等式在部署时**不可直接观测**。现有实验（H030 的 `A→B→A` cycle）用的是 Kubric 已知内参。

代价与收益是同一个来源：**不参数化相机，就不需要估位姿；但也就失去了一个免费的全局坐标系，恒等式只能靠模型自己保证，而检查它需要外部信息。** 这应该明确写进 limitation。

## 11. 速查表

```
记号：  X[s, t, p] ∈ R³     s = 参考系, t = 物理时间, p = source 像素
        φ_{s→t}(p)          像素对应；被遮挡记 ⊥
        T_{t←s}             第 s 帧相机系 → 第 t 帧相机系的刚体变换

恒等式 1（换参考系，与点无关）
        X[t, u, φ_{s→t}(p)] = T_{t←s} · X[s, u, p]
        T_{u←t} · T_{t←s}   = T_{u←s}
        T_{s←s}             = I

恒等式 2（换像素）
        φ_{t→u}( φ_{s→t}(p) ) = φ_{s→u}(p)
        φ_{s→s}(p)            = p
        φ_{t→s}( φ_{s→t}(p) ) = p

恒等式 3（换时间）
        无约束。X[s,t,p] 与 X[s,u,p] 之间差的是物质点自己的运动。

不对称性
        改 s → 换坐标（受恒等式 1 约束）
        改 t → 走时间（无约束）
        ⟹ source / target 是两种不同对象，模型里应该用两套独立 embedding，不能对称化

为什么叫 cocycle
        一族"换算表"必须满足"绕一圈回到原点"的自洽复合律。
        cycle consistency 只是它在 A→B→A 这个特例上的写法。

两种输出系
        世界系  ⇒ T = g_t · g_s⁻¹，恒等式自动成立，但必须估每帧位姿
        source系 ⇒ T 可非平凡，恒等式成为约束，不需要位姿
```
