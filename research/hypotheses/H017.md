# H017 — 30k decoder-capacity sweep

## Question

At a fixed structured Wan/geometry route, what dense decoder capacity is appropriate when the small, medium, and large models are each trained for 30,000 optimizer updates with the largest safe physical batch on one 80 GB A100?

## Prediction

Increasing the decoder from roughly 3M to 20M parameters should improve held-out dense 4D geometry. The roughly 75M arm should show whether this trend continues or saturates; if its held-out gain is negligible relative to its compute/memory cost, the 20M decoder is preferred.

## Fixed protocol

- GPUs: physical 2 / 4 / 6 for the 3M / 20M / 75M decoder arms respectively.
- Decoder-only architecture sweep with exact parameter counts:
  - 3M: `query_dim=256`, 2 cross-attention blocks, decoder parameters `2,835,523`.
  - 20M: `query_dim=512`, 5 cross-attention blocks, decoder parameters `19,259,267`.
  - 75M: `query_dim=1024`, 5 cross-attention blocks, decoder parameters `75,487,747`.
- Hold the geometry adapter at `geometry_dim=128`, hidden triad `[13,14,15]`, eight motion slots, source-local query path, and all Wan/geometry choices fixed. This avoids changing geometry-adapter capacity with decoder capacity.
- Canonical source-frame, `source_all_targets` supervision: one sampled source and all ordered targets 0..20 per clip. Use all 5,737 training clips, BF16, full Wan DiT + geometry adapter + decoder fine-tuning, seed 2029, geometry seed 2026, decoder seed 424242, and no gradient accumulation.
- Every arm runs exactly 30,000 optimizer updates. Optimizer and LR settings are identical: decoder/adapter `3e-4`, Wan `5e-5`, 256-step linear warmup, AdamW weight decay `1e-4`.
- Before formal training, independently screen physical batch capacity on the assigned GPU with a real one-step forward/backward/Adam update. Select the largest successful candidate at or below 78.0 GiB allocated, with an OOM or above-ceiling next candidate whenever the candidate range permits.
- Periodic exact-resume checkpoints are atomically overwritten every 5,000 steps under `/data/WorldBridge4D-persistent/h017_decoder_capacity`; generated weights are not committed.

## Interpretation safeguard

The user explicitly requested that each GPU be filled, so physical batch size—and therefore total clips seen over 30k updates—will differ by arm. This is a practical capacity/quality sweep, not a sample-compute-matched scientific ablation. Final model selection must report batch size, clips seen, wall time, and validation EPE together; an apparent larger-model gain cannot be attributed only to parameter count.
