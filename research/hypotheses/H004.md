# H004 — Dense-query 4D latent from feed-forward Wan

## Question

Can a minimally modified pretrained Wan2.1-1.3B map a clean MOVi-F RGB video latent through one DiT forward at rectified-flow time zero into a reusable implicit `Z4D`, such that a lightweight dense `(source,target)` cross-attention decoder predicts a complete source-grid XYZ map for arbitrary source times?

## Prediction

With the Wan VAE frozen and no direct `Z4D` supervision, validity-masked XYZ supervision over balanced diagonal and off-diagonal pairs should (1) strongly overfit fixed pairs from 1–4 clips, (2) decrease for randomly sampled forward, backward, long-gap, and `source>0` queries on the same clips, and (3) complete bounded held-out evaluation with finite pointmap, visible tracking, and occluded-valid tracking metrics. The same `Z4D` must serve every pair and retain Wan's native `[16,6,16,16]` topology.

## Falsification / gates

Do not train until native MOVi-F geometry, Wan's clean-latent shape, timestep-zero convention, and raw velocity sign pass direct audits. The feasibility claim fails if fixed-pair loss does not materially decrease, arbitrary-source loss is flat, gradients do not reach Wan DiT parameters, or the decoder cannot distinguish spatial positions using 2D RoPE.

## Fixed v1 scope

- RGB -> frozen Wan VAE mean latent -> one full Wan DiT forward at flow time zero -> verified negative raw velocity -> `Z4D`.
- Full flattened `Z4D` memory; independent learned source/target embeddings; dense 16x16 query grid; 1–2 cross-attention/FFN blocks with spatial-only 2D RoPE; bilinear 2D upsampler to 128x128 XYZ.
- No GT latent, latent loss, camera input, visibility head, source RGB patch, query self-attention, temporal RoPE, delta-time embedding, or iterative diffusion.

## Planned H004-v2 ablation screening (designed 2026-08-08; not executed)

This is a follow-up route, not evidence for H004 v1. Every arm shares two engineering changes: source-centric target enumeration and bounded asynchronous CPU geometry prefetch. Each clip selects one deterministic source time and supervises all target times `0..20`; source times rotate uniformly across visits. The producer uses eight shared-memory threads and a queue bounded at depth 2; the main process fixes the sampling plan so worker scheduling cannot change the seed. Geometry workers produce only the requested source/target targets; they do not change XYZ semantics or the `A` validity mask. All arms use the same cached MOVi samples/latents, train-only coordinate statistics, BF16, full trainable Wan, one flow-time-zero DiT forward, `batch_size=16`, `gradient_accumulation=1`, and 1,000 optimizer updates. Pair-wise XYZ weighting is fixed to `1/3` diagonal and `2/3` off-diagonal. No depth or reprojection loss is included in this screen, and no iterative DiT path is tested.

- `B0`: optimized source-centric baseline; 2D spatial-only RoPE, two cross-attention blocks, XYZ-only loss.
- `E3`: B0 with only the decoder positional encoding changed to 3D `(latent_time,u,v)` RoPE. Memory time is `0..5`, query target time is `target*5/20`, the first 24 dimensions of each 32-dimensional head are split equally across temporal/u/v rotary pairs, and the remaining eight dimensions pass through unchanged.
- `E5`: B0 with only a full-resolution one-channel visibility-logit head. Visibility uses off-diagonal masked `BCEWithLogitsLoss` with `M` targets and `A` masks. A fixed `pos_weight` is computed once from the common deterministic train schedule, recorded before formal runs, and never estimated per batch; XYZ never uses predicted visibility as a mask. Initial auxiliary weight is `lambda_visibility=0.1`.
- `E6`: B0 with only decoder cross-attention/FFN depth changed from 2 to 4 blocks; query dimension, heads, upsampler, RoPE, and loss remain fixed.

Screening uses one seed (`2029`) and the same deterministic 32-clip validation subset with exhaustive 441 legal `(s,t)` queries per clip. Primary selection is off-diagonal all-valid 3D EPE; report all-valid, diagonal, source-zero/source-positive, forward/backward, short/long-gap, visible, occluded-valid EPE, auxiliary metrics, step time, geometry/prefetch wait, GPU utilization, and peak allocated/reserved memory. A 1000-update screen is for ranking only, not a final generalization claim. The best one or two arms then receive longer fixed-budget training and multi-seed confirmation; no arm is combined with another before its single-factor result is recorded.
