# H007 — Source-frame coordinates for source-conditioned 4D queries

## Question

Does expressing each `(source=s,target=t)` source-grid XYZ trajectory in camera frame `s`, instead of the fixed clip-frame-0 camera anchor, improve arbitrary-source 4D geometry while reducing canonical-reference bias?

## Predeclared prediction

The source-frame arm should improve source-positive and arbitrary off-diagonal geometry, especially diagonal `s=t` pointmaps, long temporal gaps, and late-appearing source points. The `s=0` labels are mathematically unchanged. Overall gains are not guaranteed because predictions from different sources no longer share a common coordinate system.

## Coordinate definitions

The existing anchor arm uses

`X^(0)[s,t,p] = R_0^T (X_world[s,t,p] - c_0)`.

The source arm uses

`X^(s)[s,t,p] = R_s^T (X_world[s,t,p] - c_s)`.

The source-grid location, source/target pair sampler, visibility `M`, validity `A`, Wan latent, model architecture, and XYZ loss remain unchanged. The transform is a complete rigid camera transform, not translation-only normalization. At `t=s`, the source target is the ordinary local camera pointmap of frame `s`.

## Matched protocol

- H005 structured triad `[13,14,15]`, eight motion slots, geometry-adapter mode.
- 32 train clips, 1,536 optimizer updates, matched epoch sampling, H001-balanced nine-pair sampler.
- Seeds 2026 and 2027; decoder seed `424242`; geometry seeds equal run seed; BF16, batch size 1, same learning rates, optimizer, and architecture.
- Source arm uses train-only diagonal coordinate statistics computed over the same 5,737 train clips and valid point population as the anchor statistics, but after expressing each `P[t]` in camera `t` coordinates. Statistics are never computed on validation clips.
- Evaluation uses the exact same executable `evaluate_dense4d.py`, validation clips `0..146`, exhaustive legal 441 `(s,t)` pairs per clip, `pixel_stride=16`, `pair_chunk=8`, identical visibility/validity masks, and metric-space EPE after checkpoint-specific denormalization. Primary comparison is off-diagonal all-valid EPE; diagonal, first-frame/source-positive, visible/occluded-valid, temporal gap, and late-appearing groups are secondary.
- For a sanity check, source-frame predictions can be converted to frame 0 with the known evaluation camera poses. Per-pair metric EPE should be invariant to this rigid conversion; this conversion is not used during training.

## Falsification / safeguards

Do not claim improvement from normalized loss or a changed coordinate statistic alone. The arm must pass geometry transform/cache tests and checkpoint load tests. Report both coordinate convention and the identical evaluation protocol in every result. A source-frame model is not called permutation-equivariant: frame ordering, source/target embeddings, and the temporal video contract remain unchanged.
