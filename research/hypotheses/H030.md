# H030 — H027 step-130k Kubric pixel-cycle continuation

## Hypothesis

For an A-frame foreground boundary point that is incorrectly transferred to a
background pixel in B, querying B back to A should not return the original
pixel. A Kubric-only differentiable A→B→A pixel-cycle reprojection loss should
therefore reduce boundary tracking errors.

## Fixed protocol

- Starting checkpoint: H027 global step 130,000, SHA-256
  `9fadf33559bfd2402b2d3330c97d620f8d16d6d90820a223c07601ba504ba7b7`.
- GPUs: physical 5 and 7, world size 2, FSDP FULL_SHARD.
- H027 model/optimizer protocol otherwise unchanged: decoder-only, Wan and
  geometry frozen, source-RGB pre-attention branch retained.
- Capacity setting: microbatch 1, accumulation 4, K=13, target step 140,000.
- One maximum-gap target is selected per Kubric sample for the cycle branch.
- Cycle uses visible-visible valid points, pixel stride 4, normalized-pixel
  Huber loss, weight 0.02. The original XYZ SmoothL1 remains active.

## Prediction

Compared with an identical no-cycle continuation, fixed Kubric validation
should improve boundary EPE and forward/backward pixel error. Training cycle
loss alone is not sufficient evidence.

### 2026-09-04 — high-weight all-dataset continuation

- The initial weight-0.02 continuation was stopped at global step 147,146 at
  the user's request. Its Kubric training loss was only weakly decreasing, and
  the measured cycle term (`~2.5e-4 * 0.02`) contributed roughly 0.01% of the
  XYZ objective numerically.
- Extended the cycle camera contract to PointOdyssey and Dynamic Replica,
  including their crop/resize intrinsics and per-axis focal lengths. The new
  run uses `cycle_reprojection_weight=0.3` for Kubric, PointOdyssey, and Dynamic
  Replica, with the same exact step-140k checkpoint, seed, K=13, B1/A4, and
  physical GPUs 6/7.
- A geometry-only cycle smoke test found nonzero rasterized reference cycle
  errors on the sparse external datasets (PointOdyssey ~55 px and Dynamic
  Replica ~20 px on one long-gap sample), so this is an empirical test rather
  than an assumption that the auxiliary objective is universally conflict-free.

### 2026-09-05 — weight-0.3 result

- Run `R-20260904083805-2ef397` completed step 150,000 on physical GPUs 6/7.
  W&B run `aa94m3tl`; peak allocated memory 21.59 GiB; all metrics were finite.
- Over the exactly matched 140k--147.14k portion versus the weight-0.02
  Kubric-only run, mean training EPE changed by -0.00038% on Kubric, +0.00038%
  on PointOdyssey, and -0.00064% on Dynamic Replica: numerically
  indistinguishable. Total logged loss was higher by 0.10%, 0.47%, and 0.35%
  respectively, exactly consistent with adding the weighted cycle term rather
  than degrading the XYZ prediction.
- In the weight-0.3 run alone, first-1k to final-1k training EPE changed by
  -0.83% Kubric, -6.47% PointOdyssey, and -3.46% Dynamic Replica. This is
  continuation evidence, not a cycle effect, because the matched overlap did
  not diverge from the lower-weight route.
- Even at weight 0.3, the mean weighted cycle contribution was only about
  0.11%/0.47%/0.35% of the logged Kubric/PointOdyssey/Dynamic Replica loss.
  The mature decoder LR factor was already 0.0113 at step 140k and decayed to
  zero at step 150k. The experiment therefore does not show faster EPE descent
  from this weight change under the near-zero-LR continuation protocol.
- Durable step-150k checkpoint: SHA-256
  `aeee1383958eb9bf3f2b2311a024b41b5c93fb5991ae8f26fa4524009bad9af7`,
  artifact `artifact://H030/R-20260904083805-2ef397/checkpoint/aeee1383958eb9bf`.

### 2026-09-05 — batch-local 30%-of-XYZ normalization

- At the user's request, retain the all-dataset raw normalized-pixel Huber
  cycle, weight 0.3, model, optimizer resume, data order, B1/A4/K13, and
  140k--150k schedule, but normalize each microbatch's cycle loss to its
  detached XYZ loss before applying weight 0.3.
- The scale is `detach(L_xyz) / clamp_min(detach(L_cycle), 1e-6)`, capped at
  1000; zero/near-zero cycle losses contribute zero. This targets a weighted
  cycle scalar contribution equal to 30% of XYZ without propagating gradients
  through the scale. Added separate XYZ, weighted-cycle, ratio, and scale logs.
- Validation passed all 53 `test_training256.py` tests, config validation,
  compileall, and diff checks. The requested run uses physical GPUs 5/6.

### 2026-09-06 — normalized-cycle result

- Run `R-20260905052559-4b4a54` completed step 150,000; W&B `bmrad8ww`;
  peak allocated memory 21.59 GiB; all metrics finite. The achieved mean
  weighted-cycle/XYZ ratios were 0.2946 Kubric, 0.2932 PointOdyssey, and
  0.2996 Dynamic Replica (medians 0.30); occasional lower values came from
  the scale/epsilon safety bounds.
- Against the exactly matched unnormalized weight-0.3 run over all 10k steps,
  cycle loss improved by 1.66%/1.45%/3.36% and cycle pixel error improved by
  1.40%/1.33%/2.34% on Kubric/PointOdyssey/Dynamic Replica respectively.
  Training EPE changed by -0.0063%/+0.0213%/-0.0196%, while XYZ loss changed
  by +0.0203%/+0.0413%/+0.0113%: no detectable EPE benefit.
- The normalization materially increased gradient pressure: median pre-clip
  gradient norm rose from 1.61 to 3.25 and the fraction above the configured
  clip threshold 1.0 rose from 57.9% to 92.5%. Thus it successfully optimizes
  the cycle diagnostic but does not support the assumption that doing so also
  improves training EPE under this late, near-zero-LR continuation.
