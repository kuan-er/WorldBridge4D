# H022

## Hypothesis

A native 21-frame 512x512 MOVi-F clip can complete one BF16
forward/backward/AdamW update on one otherwise empty A100-80GB when the loaded
Wan2.1-1.3B is frozen except for rank-16 LoRA on attention/FFN linears, every
executed Wan block is gradient-checkpointed, the `[13,14,15]` readout executes
blocks `0–15`, the selected hidden states retain the native 32x32 DiT token
grid, and the Dense4D decoder processes one target at a time.

The hypothesis is falsified if this exact batch-one gate exceeds 78 GiB allocated
memory or fails before producing finite LoRA, geometry-adapter, and decoder
gradients. This is a capacity result only: the partially downloaded TFRecord and
legacy coordinate statistics are not sufficient for a quality claim.

## Evidence

Run `R-20260812095007-2cab84` produced a successful capacity artifact on
physical GPU 5 at `2026-08-12T11:35:37Z`. That successful invocation used native
MOVi-F training sample `1680`, source frame 0, target frame 20, physical batch 1,
and one source-target pair:

- RGB: `[1,21,3,512,512]`
- deterministic Wan VAE mean: `[1,16,6,64,64]`
- native Wan DiT token grid: `6x32x32` (6,144 tokens)
- structured geometry: `[1,128,21,32,32]`
- prediction: `[1,1,3,512,512]`
- valid supervised points: `262,143`
- finite loss: `2.8705361`
- registered Wan LoRA parameters: `21,872,640` across all 30 loaded blocks
- executed-prefix LoRA parameters: `11,665,408` in blocks `0–15`
- trainable geometry-adapter parameters: `1,560,705`
- trainable decoder parameters: `2,842,659`
- forward peak allocated memory: `3.6241 GiB`
- backward/AdamW peak allocated memory: `3.8605 GiB`
- finite gradients observed for LoRA, geometry adapter, and decoder
- successful-invocation marker: `WAN_LORA_512_CAPACITY_OK`

The timed model forward/backward/update region was `3.2495 s`, but it was not
CUDA-synchronized and excludes data loading, geometry construction, model
loading, and VAE encoding. The reported peak was reset after the frozen VAE was
removed, so it characterizes cached-latent Dense4D training rather than peak
end-to-end RGB training memory. The VAE encoding itself did run successfully.

Artifact:
`/data/WorldBridge4D-persistent/h022_wan1.3b_lora512/capacity_gpu5.json`.

The PRL run envelope later continued/re-entered the command and finally exited

failure is not an OOM and does not invalidate the already-written pass artifact,
but the PRL run's final status is `failed`, not `succeeded`; no retry is useful

The earlier `R-20260812094841-766173` was terminated while waiting with only
about 31 GiB free and produced no experimental evidence. A redundant retry
`R-20260812095231-1f4f0f` was terminated after the successful run became
available.

## Conclusion

The exact one-pair capacity hypothesis is supported with very large memory
headroom: the loaded Wan1.3B with rank-16 LoRA on its **executed block-0–15
prefix**, plus the compact 32-grid decoder, can train on a native 21-frame
512x512 clip on one A100-80GB. The implementation registered another
`10,207,232` LoRA parameters in unexecuted blocks `16–29`; these received no
gradients and AdamW did not allocate state for them, so they must not be counted
as participating trainable capacity. The gate's boolean gradient checks prove
at least one finite gradient in each LoRA/adapter/decoder category, not that
every individual parameter had a nonzero gradient.

This does **not** yet establish quality, all-21-target throughput, uncached
RGB-to-loss peak memory, or that 512x512 is preferable to
lower-resolution/mixed-resolution training. Formal all-target training should
compute the Wan geometry once and decode target chunks sequentially rather than
materializing all dense target outputs at once.
